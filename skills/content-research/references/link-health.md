# 链接体检（死链治理 + 线上核对）

## 为什么必须发请求实测

模型会产出**格式完全正常但打不开**的链接：日期错位、slug 拼错、把来源站首页当文章页。静态校验（正则 / 域名白名单 / 结构检查）拦不住——它们全都长得合法。唯一可靠手段是实际发请求。

## 分级判定（照抄进脚本，别自创口径）

| 响应 | 判定 | 动作 |
|---|---|---|
| 2xx / 3xx | ✅ 可达 | 放行 |
| 403 / 429 | ⚠️ 反爬拦截 | 放行（链接可能有效），只提示 |
| 404 / 410 | ❌ 死链 | 必须换真地址后再发布 |
| 000（连不上） | ❓ 本机网络不可达 | 无法判定，提示人工确认 |

- 🔴 **把 403/429 当坏链去「修」，是这套流程最大的误报源**。按响应码一刀切会把大批正常链接判死，改坏原本正确的数据。
- 🔴 **反爬重的域，404 也不等于文章不存在**：实测某头部科技媒体对机房 IP 的**真实文章**返回 404（用该媒体自己的官方帖确认文章确实存在）。做法：把已知反爬域单列成白名单，它们的 404 降级为提示、不进死链；不确定时先搜索确认文章是否存在，再决定改不改。
- 判定前统一设桌面 UA（`curl -A "<桌面 UA>"`）；沙箱内 `github.com` 常整体不可达（000），直接排除出体检范围，别当死链报。

## 修复路径（死链 → 真地址）

1. 用**标题**去搜（不是拿错 URL 猜后缀），命中后取 canonical URL。
2. 命中结果里若真出处与简报标注的站点不同，**以真出处为准**（实测：某篇文章真出处是作者个人站，简报里挂的是转载者域名下的编造路径——格式完全合法，所以一直没被发现）。
3. 同一篇可能出现在**多期**（同一 URL 多处出现）→ **全库通改**，只改当期则下一期又冒出来。
4. 改完逐条实测新地址（200 才算过），再复扫全库确认死链归零。

## 执行层（缺了就等于没做）

- 体检脚本 `~/.hermes/scripts/check_briefing_links.py --report <报告.md>`：exit 1 = 存在死链，可直接当发布门禁；`--json` 出机读结果。
- 已接入每日校验看门狗（`content_research_check_watchdog.py`，06:45，no_agent）：全过则静默、有死链才推微信。
- 静态规则同步：推荐阅读 / GitHub 段的链接**必须是文章页**（禁站点首页占位；解析不到路径就换源），由 `daily_briefing_check.py` 的 E13 硬拦。
- 🔴 **改完门禁必须拿违规样本喂一次**，看到它真的报错才算装上；再拿真实报告回跑确认零误报。

## 核对线上时的「假差异」

按「本地 vs 线上」逐字节比对时，**先确认响应非空**：网络抖动 / 被拦时 curl 返回空 body，其 sha256 是空串哈希 `e3b0c442…`，看起来像「本地已改未推」，实际什么都没取到——据此下结论会白改一轮。做法：封装带重试的取数函数（空 body 即重试几次），取到非空再比哈希；比对同时打印两侧字节数。
