# 日报表达规范：具名、可读性、禁用模式

> 适用：每日简报完整版 + 微信摘要版 + 站点数据（三者同源，改一处要同步校验）。
> 本文件是 **权威定义**；SKILL.md 只保留摘要与指向。

## 0. 依据与边界（别把研究说过头）

| 依据 | 是什么 | 不能拿它说什么 |
|---|---|---|
| 论文 **《Why is AI-generated language so hard to understand?》**，arXiv:**2610.29162**（v1，2026-10-21 提交，**预印本、未经同行评审**；Thomas Hikaru Clark / Matias B. Martin / Kyle Mahowald，纽约大学 + 得州大学奥斯汀分校）<br>一手核验：https://arxiv.org/abs/2610.29162 | 用心理语言学特征（宾语关系从句、长依存、低频 n-gram、名词转动词、名词堆叠、无生命主语+有生命动词，共六类）比较 14 个模型（9 个前沿 + 5 个小开源）的生成文本与人类文本；语料为**英文**（120 段对话 / 45 次编程会话 / 980 篇议论文，人类对照来自 OpenSubtitles 字幕、StackExchange、PERSUADE 学生作文） | 不是「AI 文本鉴定器」；没有验证中文；六类特征出现频率高 ≠ 能单独判定某段是 AI 写的 |
| `humanizer` skill（基于 Wikipedia「Signs of AI writing」，34 类模式） | 英文写作的 AI 腔清单，用于改稿时对照 | 同样不是中文语料验证过的规则集 |

**结论口径**：论文给「为什么难读」的机制（信息压缩把解释工作转给读者）；本文件给「中文日报怎么写才不累」的**适配规则**。写进文章或对外说明时，必须区分这两层，不得写成「论文证明中文该这么写」。

论文的成因解释是**假设**（奖励可验证正确、按 token 计费会鼓励高密度表达），不是已证因果；引用时写「研究者的解释是……」。

## 1. 具名规则（最高优先级，2026-11-01 用户拍板）

三种范围，**不要互相泛化**：

| 范围 | 规则 | 例 |
|---|---|---|
| ① 公开新闻事件（🎯要点 / 📌最新动态 / 🔍洞察里的引用 / 📖推荐阅读） | **必须写公司、产品、人物真名** | 「OpenAI 新一轮只募到 110 亿美元」「红果短剧年营收超 150 亿」「Reddit CEO Huffman 称……」 |
| ② 共识 / 分歧**解读句**（各 1 句，全篇共两句） | 禁具名、禁数字——真正要抽象的就是这一句 | 「AI 商业化的竞争，重心从能力展示移到了可持续的投入产出。」 |
| ②′ 共识 / 分歧**引用事件行**（`▸ 引用N`，各 3 条） | **必须写公司/产品真名 + 真数字**（2026-11-01 二审纠正：上一版误把「去具名」扩到引用行，6 条引用全变成「某平台 / 数家巨头」，用户直接打回） | 「引用1：OpenAI 新一轮募资只拿到 110 亿美元，不足 300 亿目标的一半（The Decoder）」 |
| ③ 个人数据 / 凭据 / 内部标识 | 仍必须保护（token、密钥、账号、住址、内部表 ID、版本号） | 与具名规则不冲突：企业名公开，个人凭据不公开 |

### 硬规则

1. **禁止匿名占位**：`某头部模型公司` `某营销平台` `某内容社区` `某平台` `某厂商` `某机构` `某团队` `某搜索方` `一家大体量内容社区` `云厂商`（当素材能指认到具体公司时）。
2. **真名只能来自素材**：素材条目的标题/正文/官方博客里出现的名字才能写。**不许凭印象替换**（把「某芯片公司」直接填成记忆里的公司 = 编造）。
3. **素材确实没点名**：写「报道未点名」或换一条素材；不要用「某」遮掩成"已核实"的样子。
4. **归属关系只写素材有的**：素材写「字节跳动旗下红果短剧」才写归属；素材只写红果短剧就只写红果短剧。
5. **口径一致**：摘要版与完整版对同一事件必须同一具名程度（2026-11-01 事故：摘要写 OpenAI，完整版写「某头部模型公司」）。

## 2. 六类难读特征 → 中文改写对策

论文的六类特征（英文语料），对应到中文日报的写法：

| # | 特征（论文） | 日报里的坏样子 | 怎么写 |
|---|---|---|---|
| 1 | 常见词组成罕见搭配（unattested n-gram） | 「读者耐心预算」「真实回流」「能力已不稀缺」 | 用日常搭配；确需造概念，**当句给定义**，全文只用一次 |
| 2 | 相关成分隔太远（长依存 long dependency） | 「某公司在新一轮里只募到不足原目标一半的 110 亿美元」 | 主语—谓语靠近，长定语拆成两句 |
| 3 | 宾语关系从句省略关系词（reduced object relative，论文原例 "a first name he'd never hear anyone use"） | 「团队两个月拍十一部剧拿到的钱只有九块六」——定语套定语，读者要回头找主干 | 定语拆成独立短句：「团队两个月拍了十一部剧，最后只拿到九块六」 |
| 4 | 名词层层堆叠（stacked nouns） | 「企业 AI 成本治理交付物标准化路径」 | 超过两层「的」就拆；用动词句替代名词串 |
| 5 | 名词临时当动词（denominal verbs） | 「把这个场景看板化」 | 「给它做一张看板」 |
| 6 | 无生命主语 + 有生命动词（inanimate subject + animate verb） | 「模型吃掉了预算」「平台杀死了流量」 | 「调用成本超出预算」「平台改版后引荐量下降」 |

> 上表 1–6 即论文的六类构造，别多也别少：**「省略连接词／三个因果堆一句」不在论文六类里**，那属 humanizer 与中文改写的适配规则，单列在 §3 第 5 条。引用论文时按上表说，不要说成「论文发现中文该这么写」。

## 3. 句子级五条（校验器管不到，生成时必须自检）

1. **完整主谓宾**：一句话一个判断；不写只有名词短语的"结论句"。
2. **事实 / 推断 / 行动三层分开**：📌 只写发生了什么（谁、做了什么、数字带口径）；🔍 才能写推断，且标明是推断；💡 只写读者能执行的动作。不把推断塞进 📌，不把事实重复进 💡。
3. **数字带口径**：谁说的、哪段时间、跟什么比。「募到 110 亿美元，目标是 300 亿」；不写「大幅低于预期」代替数字。
4. **不用抽象名词句当结论**：`同一把尺子` `底层逻辑` `赋能` `抓手` `闭环` `范式转移` `正在变成` `不是 A，而是 B`（连用）。
5. **连接词显式（中文适配，非论文六类）**：一句一个因果，写出「因为/但/所以」；不把「募资缩水，投资人转冷，估值下调」三个因果并排堆在一句里。

## 4. 禁用模式（附真实反例 → 改写）

| 模式 | 反例（2026-11-01 实际产出） | 改写 |
|---|---|---|
| 匿名占位 | 「某头部模型公司新一轮仅募到约 110 亿美元」 | 「OpenAI 新一轮只募到 110 亿美元，目标是 300 亿」 |
| 抽象词堆叠 + 伪因果 | 「能力已不稀缺，能否证明真实回流才是关键：募资、采购、分账在量同一把尺子」 | 「募资、采购、分账都在问同一件事：这笔投入换回了多少能核对的收入」 |
| 生造比喻 | 「新芯航途成了 Momenta 的硬通货伙伴」 | 「新芯航途与 Momenta 有股权关联，首款芯片用 Momenta 的 R7 世界模型做评测」 |
| 翻译腔判断句 | 「值得注意的是，这标志着……」「在 AI 基建的背景下」 | 直接写主句：「五家巨头承诺投入超 3 万亿美元建数据中心」 |
| 硬压缩（把解释甩给读者） | 「订阅升档前按「峰值并发 × 任务时长」算真实用量」 | 「先用峰值并发乘以单次任务时长，估出每月实际用量，再决定升不升档」 |
| 悬念对仗 / 三段排比 | 「一边……一边……；前者赌时间，后者赌账本」 | 平铺两个事实 + 一句取舍，不强行对仗 |
| 空转判断 | 「意义重大」「值得关注」「影响深远」 | 写影响落在谁身上、下次看哪个数字 |

## 5. 校验与例外

- `~/.hermes/scripts/daily_briefing_check.py`
  - **E16（error）**：新闻区（🎯 / ❶❷❸ / 📖）出现匿名占位 → 阻断。
  - **E17（warn）**：抽象套话 / 单句过长（>45 汉字无标点）→ 提示，不阻断。
- **例外（必须遵守，防误伤）**：
  - 引号内 `「…」` `“…”` 的原文引用、用户原话、规则说明（含「禁止写某平台」这类否定表述）**不参与 E16 拦截**——检测前先剥离引文。
  - 回指式指代（「该公司」「该平台」「该搜索方」）**只在同句或上文没有具名线索时才拦**：前一条 ▸ 已经写了 OpenAI / 红果短剧 / AWS 这类真名，再写「该公司」是正常中文，不得判 E16；来源标签（The Decoder L3）不算具名线索。
  - 共识/分歧段：**只有「解读」那 1 句不受 E16**（它本就要求去具名，改由 E18 管多句/数字/具名）；**「▸ 引用N」行反过来允许且要求写真名真数字**（公司/产品/人物），E19 对引用行的匿名占位只提示不拦——两套规则别互相泛化。权威源：`references/consensus-division-rules.md` v2.0。
  - E17 只提示不阻断：抽象词在引用原文里出现是正常的。
- **改规则后必须回归（三个样例，缺一不可）**：正样例（今天的具名版报告）应 0 error；反样例（把某条改成「某头部模型公司」）应报 E16；回指正例（「OpenAI …；该公司 …」）**必须通过**，防把正常回指一起拦了。只喂正样例等于没测。

## 6. 与站点/发布的关系

- 站点数据由日报 md 构建；**日报具名，站点才具名**。构建脚本的脱敏规则只处理个人/账号标识（主理人人设等），**不得把公开企业名加入脱敏表**。
- 发布前额外核对：`site/data/*.json` 里不应出现「某+公司/平台/机构」式占位（`build_site_publish.py` 会报告，见 `references/link-health.md` 同级门禁）。
