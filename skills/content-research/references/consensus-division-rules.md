# 共识/分歧段落硬约束（唯一权威源）

> 🔴 **本文件是「共识/分歧」硬约束的唯一权威定义**。SKILL.md / output-template.md / cron prompt 三处一律用「参考 references/consensus-division-rules.md + 跑 scripts/consensus_check.py」引用，禁止在多处复制粘贴同一段规则。
>
> 历史背景：
> - 2026-08-21 用户拍板。原报告的「共识/分歧」段落核心结论+扩展说明里堆叠了「Ramp Router（降本40%）、Stripe收购OpenRouter（溢价5.4x）、阿里AI ARR破百亿」一类的事件罗列，不是机制层结论；同日改造升级为「单点收拢」架构，规则只放本文件。
> - **2026-11-01 用户二审纠正（v2.0）**：上一版把「去具名」泛化到了整段，连「▸ 引用N」行也写成「某平台 / 数家巨头 / 新一轮募资」，导致引用失去可核查性。用户明确：**真正要抽象的只有「解读」那 1 句，引用行必须写真名真数字**。同时解读从「1 句结论 + 1-2 句扩展」压到**每块只 1 句**。

## 段落的两个区域（结构即判据）

```
**🔵 共识解读**
<解读句：1 句，只说本质，禁具名、禁数字>      ← 区域 A
**引用事件：**
▸ 引用1：<具体事件 + 公司/产品真名 + 真数字>（来源）   ← 区域 B
▸ 引用2：…
▸ 引用3：…
**🔴 分歧解读**
<解读句：1 句>                              ← 区域 A
**引用事件：**
▸ 引用1-3：…                                ← 区域 B
```

## 硬约束规则

1. **解读（区域 A）每块恰好 1 句**，共识 1 句 + 分歧 1 句 = 全篇两句。写的是**本质结论**（谁在按什么标准竞争、分歧在哪一层），不是新闻现象。不要「核心结论 + 1-2 句扩展」的旧结构。
2. **解读句禁具名、禁数字**：不出现公司/产品/人名、不出现任何数量（`110 亿 / 3 万亿 / 98.7% / 25% / 三成` 这类都不行）。理由：解读是抽象层，名字与数字一进来就变成复述新闻。
3. **解读句不重复引用里的新闻现象**：引用行已经写了「谁募了多少、谁的分账跌了」，解读句再讲一遍等于把同一句话写两遍。判据：把三行引用全删掉，解读句仍应是成立且可读的判断。
4. **引用（区域 B）恰好 3 条/块，必须写真实公司、产品、人物与真实数字**——引用行的价值就是可核查，匿名化等于作废（2026-11-01 事故：6 条引用全部被写成「某平台 / 数家巨头 / 顶级套餐」，用户直接打回）。真名真数只能来自当日素材（标题/正文/官方博客），**不许凭印象把「某公司」替换成记忆中的名字**；素材确实没点名就写「报道未点名」或换素材。
5. **引用与解读之间空一行**，且引用行格式固定 `▸ 引用N：…（来源）`。引用行内禁 URL。
6. **反例（禁止再出现）**：
   - ❌ 旧式多句解读（2026-11-01 被打回那版）：「募资、采购、分账三条线都在问同一件事：这笔投入换回了多少能核对的收入。募资只到原定目标的一小半；企业采购开始追问单任务成本…AI 的估值标准也跟着变了…谁的账算得清，谁才拿得到下一轮资源。」
   - ❌ 解读句具名/带数：「OpenAI 只募到 110 亿美元，说明商业化转向投入产出。」
   - ❌ 引用行匿名（把去具名泛化到引用）：「▸ 引用1：新一轮募资只到原定目标的一小半（The Decoder）」「▸ 引用1：多家科技巨头承诺投入超三万亿美元（IT之家）」
   - ❌ 事件罗列句冒充结论：「Ramp Router（降本40%）、Stripe收购OpenRouter（溢价5.4x）、阿里AI ARR破百亿——三方独立信号指向同一结论」
7. **正反对照（以用户最终认可的聊天原句为准，不以执行者另写的替代句为准）**：
   - ✅ 共识：**AI 商业化能否持续，取决于投入能否转化为可验证的回报。** 直接说明成立条件与判断标准，没有声称整个行业已经完成转向。
   - ✅ 分歧：**扩张应由未来需求预期驱动，还是由已验证的回报约束。** 两边都是决策依据，清楚揭示预期驱动与回报约束的取舍；「预期」明确未来需求尚未验证。
   - ❌ 共识替代句：「AI 商业化的竞争，重心从能力展示移到了可持续的投入产出。」把机制判断降成趋势描述，并增加「重心已经转移」这一需额外证据的断言。
   - ❌ 分歧替代句：「分歧在于用未来需求支撑当下扩张，还是用已验证的回报约束投入。」加入「分歧在于」复述标题，用「未来需求」淡化了预期的不确定性，句式更绕。
   - 后续写作借鉴正例的判断层级，不照搬主题和词句：共识提炼成立条件、因果机制或共同判断标准；分歧提炼对立的决策依据、约束或价值取舍。先保留有信息量的条件词，再删铺垫和现象。不得为了压字数删掉业务区别。
   - 用户已认可的句子逐字锁定。发布前与认可原文比对；执行者不得再润色，自动格式通过不代表语义和文案获认可。

   **以下两句是被否决的替代稿，仅保留为反例取证，不得再次当作正例：**
   - ❌ 共识：**AI 商业化的竞争，重心从能力展示移到了可持续的投入产出。**（1 句、无名字无数字、不重复引用）
     引用1：OpenAI 新一轮募资只拿到 110 亿美元，不足 300 亿目标的一半，估值 1.25 万亿美元低于预期（The Decoder）
     引用2：红果短剧年营收超 150 亿、日活 1.68 亿，但万次播放收益从百元跌到 5 元，98.7% 的 AI 短剧未回本（知乎）
     引用3：AWS 发布 Amazon Bedrock 成本治理手册，把花费归属、预算执行与复盘节奏写成常规流程（AWS）
   - ❌ 分歧：**分歧在于用未来需求支撑当下扩张，还是用已验证的回报约束投入。**（1 句、点出结构性对立）
     引用1：微软、谷歌、甲骨文等五家巨头承诺未来数年在数据中心等领域投入超 3 万亿美元（IT之家）
     引用2：Reddit CEO Steve Huffman 称 Google AI 摘要不为任何站点带流量，Reddit 十月每周损失超百万次引荐，股价跌超 25%（The Decoder）
     引用3：Anthropic 把 Claude 顶配 Max 20x 更名 Ultra，取消五小时限额，月费 200 美元不变（36氪 / 量子位）
8. **不装确定趋势**：解读句里避免「必将 / 正在变成 / 已经彻底」这类预言式断言；证据只支持到哪儿就写到哪儿（「重心移到」可以写，「格局已定」不行）。

## 校验方式（自动化）

报告生成后/交付前**必须**跑统一校验（含 E18/E19 两条共识分歧规则）：

```bash
python3 ~/.hermes/scripts/daily_briefing_check.py $(date +%Y-%m-%d)
```

| 规则 | 判据 | 级别 |
|---|---|---|
| E18 | 解读句 >1 句 / 出现数字 / 命中具名黑名单 | error（生效日 2026-11-02 前降为 warn） |
| E19 | 引用行没有具名主体（去掉行尾来源括注后无公司/产品名） | warn |

实现位置：`~/.hermes/scripts/daily_briefing_check.py` 的 `check_file()`（常量 `QUOTE_BLOCK` / `NUM_IN_CONSENSUS` / `CONSENSUS_RULE_SINCE`）。
`scripts/consensus_check.py` 是旧版专项脚本，仅作历史兼容；新规则以统一校验器为准。

**生效日为什么是 2026-11-02（迁移日期，写清楚免得被当成硬编码）**：本规则 2026-11-01 由用户二审拍板，而 2026-11-01 当天报告（IMA 笔记 7522475889930858）已按旧口径（1 句结论 + 1-2 句扩展）通过并交付，不能反过来判它不合格。因此 `CONSENSUS_RULE_SINCE = "2026-11-02"` 表示「**11-02 及以后生成的报告一律按 E18 error 判**，此前的历史报告回跑只降为 `[历史口径]` warn」。这是一次性的迁移边界，不是「未来某天再生效」的悬空规则，也不要为了回溯历史去改它。

**改这条规则必须正反样例双跑**：正例=当天二审稿 0 error；反例=把解读句拆成 3 句或多写一个「110 亿」→ 必须 error；再把一条引用改回「某平台」→ 必须出 E19。只喂正例等于没测（2026-11-01 实测：E19 最初被行尾来源「（知乎）」骗过，静默不报，补了剥尾逻辑才生效）。
