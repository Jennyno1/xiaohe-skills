# 共识/分歧段落硬约束（唯一权威源）

> 🔴 **本文件是「共识/分歧」硬约束的唯一权威定义**。SKILL.md / output-template.md / cron prompt 三处一律用「参考 references/consensus-division-rules.md + 跑 scripts/consensus_check.py」引用，禁止在多处复制粘贴同一段规则。
>
> 历史背景：2026-08-21 用户拍板。原报告的「共识/分歧」段落核心结论+扩展说明里堆叠了「Ramp Router（降本40%）、Stripe收购OpenRouter（溢价5.4x）、阿里AI ARR破百亿」一类的事件罗列，不是机制层结论；同日改造升级为「单点收拢」架构，规则只放本文件。

## 硬约束规则（编号 1-6）

1. **「核心结论」+「1-2 句扩展说明」里禁止出现任何具名事件、品牌名、并购对象、产品名、数字**——一句话加粗 + 1-2 句机制说理，不重复「发生了什么」。事件名/数字/品牌/收购方/被收购方/股价涨幅/ARR 数字 一律禁止出现在这两段。
2. **事件名、数字、引用源只允许出现在「引用事件」一行**（每条 ▸ 引用N：来源名），且这一行必须跟前面的核心结论+扩展说明在视觉/语义上明显区分（中间用空行隔开）。
3. **写法自检清单**（生成后必须执行）：
   - 把核心结论+扩展说明单独复制到新文档；
   - 把所有「引用事件」行全删掉；
   - 如果删完后段落失去信息量或读不懂 → 说明还在罗列事件，必须重写。
4. **反例（2026-08-21 实测，禁止再出现）**：
   - ❌ "Ramp Router（降本40%）、Stripe收购OpenRouter（溢价5.4x）、阿里AI ARR破百亿——三方独立信号指向同一结论"
   - ❌ "WRC 2026'今年都在关心场景'vs 量子位报道强调'具身大脑'"
   - ❌ "宇树上市+629%只验证资本市场对'能交付产品公司'的偏爱"
   - ❌ "Ramp三年内部经验商业化、OpenRouter被Stripe抢购、阿里AI ARR破百亿——三方独立信号指向同一结论"
5. **正例（同样信息量，砍掉事件后的写法）**：
   - ✅ 共识：**AI 用得越深的企业，反而最先为「成本管理」付钱——卖水人比淘金者更早规模化。** 当企业同时跑多个模型、token 价差十倍、没人说得清花销归谁时，统一路由+成本可视化就从可选项升级成硬需求；这跟当年云迁移刚启动时先冒出成本治理工具，是同一个商业周期位次。
   - ✅ 分歧：**具身智能押「现在能交付的客户」还是押「未来通用智能的赢家」——这是同一技术在两个商业周期下的赌博，不存在谁对谁错。** 前者用真实订单养活团队、把每一笔合同变成下一轮融资的台阶；后者赌一次范式突破就能拿到指数回报。本质都是赌周期，只是押注压在不同的赔率窗口上。
6. **如果上面 4 条反例任一条仍出现在生成结果中，整篇报告视为不合格，必须重写共识/分歧段落再交付。**

## 校验方式（自动化）

报告生成后/交付前，**必须**调用：

```bash
python3 ~/.hermes/skills/digital-twin/content-research/scripts/consensus_check.py \
    --report ~/hermes-output/content-research/content-research-$(date +%Y-%m-%d).md
```

退出码：
- `0` = 合规，可交付
- `1` = 检测到反例，必须重写（脚本会指出违规位置）
- `2` = 文件读取/解析错误

校验脚本实现逻辑详见 `scripts/consensus_check.py`。
