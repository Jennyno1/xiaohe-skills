# 每日简报输出格式规范（权威规则源 v8.0）

> 所有格式规则集中在此文件。cron prompt / skill / 质量校验均引用本文件，不自造规则。
> v8.0 新增：信息源类型标签 + 企业案例 + Weak Signals 融入规则。

## 一、链接规则

### 允许出现链接的位置（仅两处）

1. **⭐ GitHub 推荐** — 用 `[文字](URL)` 格式
   - ✅ `[ComfyUI](https://github.com/Comfy-Org/ComfyUI)`
   - ❌ `ComfyUI https://github.com/Comfy-Org/ComfyUI`（裸URL）
   - ❌ `[ComfyUI](https://github.com/Comfy-Org/ComfyUI) https://example.com`（多余URL）

2. **📖 推荐阅读** — 用 `[标题](URL)` 格式
   - ✅ `[Hugging Face reportedly in talks to be acquired](https://techcrunch.com/...)`
   - ❌ `Hugging Face reportedly in talks to be acquired (https://techcrunch.com/...)`（URL 暴露在括号外）

### 禁止出现链接的位置

3. **▸ 引用事件行** — 只写事件描述 +（来源名），不带任何 URL
   - ✅ `▸ 引用1：Hugging Face 据报以 130 亿美元估值洽谈出售（TechCrunch）`
   - ❌ `▸ 引用1：[Hugging Face reportedly in talks](https://techcrunch.com/...)`（微信渲染炸掉）
   - ❌ `▸ 引用1：Hugging Face 据报出售 https://techcrunch.com/...`（原始URL暴露）

4. **📌 最新动态 / 🔍 洞察发现 / 💡 落地行动** — 纯文字，零链接
   - ✅ `▸ 字节将 TRAE 和扣子并入豆包体系，推出"豆包工作"品牌（36氪）`
   - ❌ `▸ 字节[将TRAE并入豆包](https://36kr.com/...)（36氪）`

5. **🎯 今天要点** — 纯文字，零链接

6. **📊 共识/分歧段落** — 核心结论 + 扩展说明纯文字；引用事件只写来源名
   - 🔴 中文句子里禁止混入无关英文词（产品名/机构名除外）——2026-09-22 事故：「基础研究进入 impressed 观察窗口」
- 🔴 `▸ 引用N：` **只允许出现在「最大共识与分歧」段**；写进 📌/🔍/💡（尤其落地行动）即违规（E13 硬拦，2026-09-22 实测 9 条越界）

### 链接格式统一要求

- 所有链接必须是 **完整 URL**（从 feed 数据提取的实际 link 字段）
- 禁止出现 `...` 省略号（如 `https://openai.com/index/...`）
- 禁止出现 `[来源名]` 代替链接
- 微信会把 `[text](url)` 中的完整 URL 也显示出来——这就是为什么引用事件行禁止带链接

## 二、引用事件格式

### 共识/分歧段落的引用事件

```
▸ 引用1：[具体事件描述]（来源名）
▸ 引用2：[具体事件描述]（来源名）
▸ 引用3：[具体事件描述]（来源名）
```

- 每条引用独占一行
- 前缀固定为 `▸ 引用N：`
- 来源名用中文全角括号 `（）`
- **引用事件里禁止出现任何 URL**——微信渲染 `[text](url)` 会把完整 URL 暴露出来
- 引用事件里禁止出现数字（金额/百分比/估值等）——数字只在「核心结论+扩展说明」中以机制化方式出现

### 赛道📌最新动态的引用格式

- 每条 `▸` 后跟完整句子，末尾标注来源名
- 来源名用中文全角括号
- 不带 URL

## 三、结构规则

### 完整版（IMA保存）结构（v8.2）

```
📋 **每日简报 · M月D日**

🎯 **今天要点**（3条•列表，每条≤30字，无括号补充）

🤖 **AI产业技术**
  📌 **最新动态**（▸ 列表，每条≤35字）
  🔍 **洞察发现**（▸ 列表，含🟡弱信号）
  💡 **落地行动**（▸ 列表，1-2条）

💼 **企业AI应用**
  📌 🔍 💡（同上）

🎨 **内容创作**
  📌 🔍 💡（同上）

⭐ **Github推荐**（● [name](url) ⭐XXK 格式）

📊 **最大共识与分歧**
  🔵 共识解读（核心结论+扩展+引用事件）
  🔴 分歧解读（同上）

📖 **推荐阅读**（每条三行：① [标题](URL) — 来源 / 📝 文章介绍 / 💡 推荐理由；禁裸 URL，不写标签词）

*信息源 + 生成日期*
```

### 精简版（微信推送）结构

```
📋 今日简报 · M月D日

🎯 **今天要点**

• [一句话事实，≤45字]

• [一句话事实，≤45字]

• [一句话事实，≤45字]

🎨 **内容创作**

📌 [1句最新动态]

🔍 [1句洞察]

💡 [1句落地行动]

💼 **企业AI应用**

📌 [1句最新动态]

🔍 [1句洞察]

💡 [1句落地行动]

🤖 **AI产业技术**

📌 [1句最新动态]

🔍 [1句洞察]

💡 [1句落地行动]

⭐ **GitHub推荐**

[项目名] ⭐[精确星数]：[一句话说明]

[项目名] ⭐[精确星数]：[一句话说明]

[项目名] ⭐[精确星数]：[一句话说明]

📊 **共识与分歧**

共识：[一句话结论，禁止具名事件/品牌/数字]

分歧：[一句话结论，禁止具名事件/品牌/数字]
```

**精简版铁律（v8.1）：**
- ≤600 CJK字
- 结构对齐完整版，**去掉📖推荐阅读**
- 🎯要点3条，每条≤35字，**禁止括号补充**
- 各赛道📌/🔍/💡各1句话，每句≤40字
- ⭐GitHub星数**必须用GH_TOKEN+API获取精确值**
- 📊共识/分歧**禁止具名事件/品牌/数字**
- 不含📖推荐阅读
- 微信分行铁律：•/⭐之间必须有空行

### 分行铁律

- `•` / `▸` / `●` / `⭐` 之间必须有**空行**（微信单换行会被合并）
- 一级标题后必须空一行再写内容
- 📌🔍💡 后加**加粗二级标题**，标题后空一行
- 无 ━━━ 分割线

## 四、字数限制

| 版本 | 字数上限 |
|------|---------|
| 完整版 | ≤2500字（信息密度优先） |
| 精简版 | ≤400字 |

## 五、共识/分歧段落硬约束

### 核心结论 + 扩展说明（▸ 引用事件之前的部分）

- 禁止出现具名事件/品牌名/并购对象/产品名/数字
- 只说机制层面的「为什么」
- 实词数 ≥ 30

### 自检三步

1. 删掉所有 `▸ 引用N` 行后，段落是否还能读懂？
2. 核心结论是否揭示了底层机制（不是复述现象）？
3. 分歧是否是同一问题的不同解法（不是不同话题的正反面）？

## 六、信息源类型标签（v8.0）

报告底部信息源行使用🏷️标签标注来源类型：
- `官方一手(OpenAI/NVIDIA/Anthropic等)` → 🏷️official
- `独立分析(Simon Willison/Latent Space)` → 🏷️analysis
- `中文媒体(36氪/虎嗅/IT之家)` → 🏷️cn_media
- `企业案例(各厂商Customer Stories)` → 🏷️industry_case
- `社区信号(GitHub/HN)` → 🏷️community
- `弱信号(跨源综合)` → 🏷️weak_signal

## 七、Weak Signals 融入规则（v8.0）

Weak Signals 不是独立栏目，融入现有结构：
- **🎯 今天要点**：当天最有价值的 weak signal 可占1条要点
- **各赛道 📌🔍**：相关 weak signal 融入对应赛道的洞察发现
- **🔵 共识解读**：升级为回答"什么共识正在形成/打破"
- **📖 推荐阅读**：能解释 weak signal 的关键文章优先推荐

## 八、企业案例融入规则（v8.0）

企业客户案例不新增独立栏目，根据内容性质融入：
- 生产部署/规模化案例 → 赛道❷ 企业AI应用 📌
- 行业应用/垂直场景 → 对应赛道 📌
- 重大案例（Government/Finance/Healthcare）→ 可进入 🎯 今天要点

## 九、采集降级披露（2026-09-23 新增）

预采集脚本的摘要末尾会附「🏥 源健康检查」。**抓取失败不能静默**——它既是读者的知情权，也是排查线索。

判据（与 `~/.hermes/scripts/check_source_health.py` 同口径）：
- **抓取失败**：该源今天 0 条产出，且 feed 文件缺失 / <200B / 解析不了（错误页、429 页）。**必须披露。**
- **无新条目**：feed 抓到了、窗口内确实没有新内容（如 NVIDIA 官方博客，最新一篇在 7 月）。**不是故障，不要报。**

披露方式：
- 抓取失败 **≥2 个源**，或素材池 **<30 条** → 微信摘要末尾追加一行：`⚠️ 源异常：<失败源名，顿号分隔>`
  （与「⚠️ 校验：…」同规格，属全篇唯一允许的额外行之一）
- 抓取失败 **≥5 个源**，或素材池 **<15 条** → 除上述一行外，**全量版文末**补一句说明本期素材偏少的原因
- 单源失败（1 个）不必进简报正文——**独立告警任务（每日 06:30）会推送**，不要在正文重复

自检：写完后跑一次 `python3 ~/.hermes/scripts/check_source_health.py` 复核失败源数，与自己写进摘要的一致再交。

## 十、同日多份与站点取材口径（2026-09-23 新增）

**结论：站点只吃 `content-research-YYYY-MM-DD.md` 一个标准文件名，同日多份不会产生歧义。**

造据（`site/build_site_data.py`）：
- `date_from_filename()` 用 `re.fullmatch(r"content-research-(\d{4}-\d{2}-\d{2})\.md", name)` —— **严格全名匹配**；
  不匹配的（`-weixin.md` / `.v7.md` / `-summary.md` / `-ai-content-creation.md`）直接 `continue` 跳过。
- 产出 `site/data/{date}.json`，一日期一份 —— 重跑即覆盖，幂等。
- 每次构建都**全量重建**（按文件名排序扫全部报告），不是增量；任何一天报告被改写，下次构建就同步。

操作铁律：
1. **重跑某天日报必须写回同一个标准名**（覆盖）——站点自然拿到最新那份。
2. **想另存版本稿就用衍生命名**（`-v2` / `-重跑` / `.v2.md`）——站点看不见它，不会误用。
3. 🔴 **绝不能用能匹配标准名的变体去顶**：历史上 `content-research-2026-08-28.v7.md` 这类文件在宽松日期提取下
   **覆盖过当天的标准产出**（解析为空 → 抹掉当日数据）。这就是严格全名匹配存在的原因，不要改宽。
4. 站点每日 07:10 由 `site_autopublish.sh` 重建；**盘中重跑报告不会自动上站**，需手动补跑构建+发布。

自检：`cd ~/hermes-output/content-research && python3 -c "import re,pathlib,collections;n=[p.name for p in pathlib.Path('.').glob('*.md')];d=[m.group(1) for x in n if (m:=re.fullmatch(r'content-research-(\d{4}-\d{2}-\d{2})\.md',x))];print(collections.Counter(d).most_common(3))"`（出现计数 >1 即异常）
